# 职业资产统一运行模型

## 1. 先建系统，不先建文件

把简历、网站、案例、招呼语、多语言版本和投递包视为同一职业证据系统的不同投影。所有载体共享五层真源：

| 层 | 要回答的问题 | 典型记录 |
|---|---|---|
| 事实层 | 发生了什么，谁做的，证据多强 | 经历、数字、时间、主体、来源、公开性 |
| 判断层 | 招聘者应因此相信什么 | 岗位价值、级别、差异点、证据缺口 |
| 载体层 | 每个触点承担哪次招聘决策 | 招呼语、简历、首页、深页、作品、面试 |
| 表达层 | 文字与视觉如何降低理解成本 | 信息顺序、语言版本、设计 token、组件关系 |
| 发布层 | 哪个源生成哪个成品，当前到哪一状态 | 生成源、候选、确认、待发布、已部署、反馈 |

先更新上游真源，再重生受影响载体。禁止在多个成品里分别修同一事实或规则。

## 2. 招聘决策链

所有载体共同服务以下决策，但不必每个载体都完成全部步骤：

1. **注意**：这是否与当前岗位相关；
2. **识别**：候选人处于什么责任层，解决哪类业务问题；
3. **相信**：哪些职责、动作和结果足以支持该判断；
4. **区分**：与同级候选人相比，差异为何值得记住；
5. **深读**：哪里可以验证判断、取舍、过程与边界；
6. **行动**：招聘者下一步应打开、询问或联系什么。

所谓“金句”不是独立目标。只有一句话同时降低理解成本、增加招聘判断且有证据承接时，才保留。口号、岗位定义和自我宣言不能替代证据。

## 3. 一条主张的最小模型

每条主张至少记录：

`读者任务 → 业务问题 → 主体与责任 → 判断／动作 → 结果或证据 → 时间与口径 → 公开边界 → 承接位置`

对每个触点再补四格：`当前目的 / 前序输入 / 下一环依赖 / 当前证据门位`。这四格用于定位当前工作，不要求把整条链路写进简历或首条消息。

完整闭环是优先项，不是强制补全模板。不存在预算、管理、发布、投放、留存或复购时，不根据职位常识补写。

同一事实可以在不同载体中承担不同粒度：入口提出判断，简历给职责与结果，深页给过程、取舍与边界。硬事实一致，句子不必一致。

## 4. 从校园与早期工作经历提取证据

从用户已经讲到的一件事开始，按“当时要完成什么 → 本人具体做了什么 → 留下什么可查材料 → 对目标岗位意味着什么”组织。先找课程报告、作品、版本记录、活动方案或实际反馈，再问决定主张强度的一个细节。称谓、奖项和组织规模只交代环境；岗位能力由本人动作支持。

| 材料场景 | 优先还原的细节 | 能形成的表达 |
|---|---|---|
| 课程／毕业设计 | 本人负责的分析、制作、方法选择、交付与评阅 | 项目目标、本人方法及可展示作品；按课程项目呈现 |
| 社团／志愿活动 | 服务对象、分工、协调动作、现场调整与记录 | 组织、沟通或执行能力；按本人实际责任表达 |
| 实习／兼职 | 交办目的、独立完成与协助部分、修改反馈、采用情况 | 对岗位具体任务的贡献及支持材料 |
| 毕业后第一份工作 | 责任变化、反复能完成的任务、成果与团队条件 | 已有能力与下一岗位要求的对应，未必沿用上一份职位名称 |

合成例：用户说“社团办了三百人活动，我负责报名表和签到，临时增设了补签入口”。可写“负责活动报名与现场签到，针对漏签增加补签入口”；三百人属于活动规模，不写成独立统筹三百人团队，也不推算效率提升。若补签机制由别人决定，改为“按现场方案增设补签入口”。同一纠正要传到简历和面试故事。

### 方向比较与面试承接

方向未定时，从已有经历提出少量真实不同的候选，把目标岗位的任务与本人证据、愿意持续做的事和现实条件逐项比较。用一份有来源的岗位说明、一个可承担的小任务或一次具体从业经历核实最关键差异；直接完成比较或样例，不要求先选定终身职业。用户已有明确岗位时直接做对应求职材料。

面试准备继续使用同一事实层：围绕岗位关心的能力，组织本人判断、动作、结果和可追问细节；要回答稿就给稿，要模拟就以一个相关问题开始并等待真实回答。每轮根据回答追问具体选择、证据或换情境后的做法；反馈引用实际回答，只将用户确认的新事实回填经历。用户喊停就结束，要接续时保留问题、实际回答及暂停点。未被真实面试官问过的问题只作演练设定。

本入口可以独立完成这些求职任务。已安装 `zane-workbench-career` 且其演练或职业比较方法有增益时，可复用相应方法，由当前主责交付同一份结果和记录；安装、入群或购买均不是继续求职的条件。

## 5. 目的、阶段与公开信息的分工

每个载体先记录它要促成的决定和下一环，再决定事实呈现的粒度。简历与作品集的首要任务是可信证明能力并争取面试；面试与后续尽调再展开复杂归因、经营限制和敏感细节。不能说假话，但没有必要在首触点一次说完全部后台事实。

只有会造成重大误导、法律／合规／隐私风险或直接改变当前招聘判断的事实才阻断公开；其他边界按招聘必要性与后续承接位置处理。风险说明不能抢走入口的判断任务，也不能把“尚未完成全面验证”自动写成“不适合发布”。

## 6. 从不确定性决定工作深度

| 情况 | 做法 |
|---|---|
| 事实与偏好清楚、改动局部可逆 | 直接生成一个有依据的候选，并做反事实检查 |
| 定位、结构或视觉存在真实分叉 | 给 2—3 个关系机制不同的方向 |
| 事实冲突、阻断公开风险或高代价发布 | 先停在诊断与证据处理；可带着走的风险进入后续承接 |
| 用户明确一次性完成 | 自主完成候选、内部多轮 QA，不伪造用户确认 |

“至少两个方案”不是机械仪式。只有第二方案能检验一个真实假设时才生成；换色、镜像和同骨架改标题不算新方案。

## 7. 多语言是市场版本，不是翻译层

多语言版本共享事实层，分别建立读者、术语、叙事和排版合同：

- 核实官方品牌名、法定主体名与公开产品名，找不到时不自造；
- 保留数字、时间、单位、证据类型、职责主体和不确定性；
- 允许模块标题、序号、句长、证据顺序和页面密度按目标市场重写；
- 不把中文长文的并列、宣言、完整收束和管理哲学逐句搬到英文；
- 由目标语言读者做独立编辑，再与源语言同尺度比较信息重量和视觉节奏；
- 信息图按目标语言重新布局，不能只替换字符串。

涉及特定国家或招聘市场时，按[目标市场适配协议](market-localization.md)验证当前规则，不把“通用英文简历”冒充当地惯例。

## 8. 设计系统不是固定模板

每个项目从 `候选人气质 / 岗位信任机制 / 证据形态 / 真实资产 / 用户偏好与反偏好` 推导设计约束。固定的是关系原则：

- 模块外间距大于模块内间距；
- 标题与上一块分离、与下一块归属；
- 视觉权重匹配招聘重要性和证据强度；
- 页面密度服务阅读，不以挤满或留白为目标；
- 组件必须表达顺序、对比、范围、层级或行动；
- 同一视觉语言不等于所有页面使用同一骨架。

颜色、字体、卡片、照片、动效、页数和页面数量都是项目变量，不进入 Skill 默认模板。

## 9. 发布与现实验证

每个资产独立记录状态：`draft → candidate → confirmed → release_ready → deployed → real_world_validated`。网站已部署不代表简历已确认；上传成功不代表线上验收；内部 QA 不代表招聘市场验证。

发布时记录权威源、发布目标、公开 URL、部署标识、检查页面与时间。只有真实投递、面试或招聘反馈才能进入现实验证。
