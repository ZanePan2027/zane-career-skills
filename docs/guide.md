# 从一段经历到简历和面试

[安装与更新](install.md) · [能力目录](skill-inventory.md) · [English](guide.en.md)

第一次使用，从 `zane-career-assets` 开始。已有简历、课程报告、作品或岗位说明时直接提供；也可以先讲一件做过的事，由 Agent 追问会影响表达的事实。

下面是一段**虚构教学示例**，用来展示输入、成果、练习和纠正之间怎样衔接，不代表真实求职结果。

## 1. 提供经历和用途

```text
请使用 zane-career-assets。
我准备申请活动运营实习。学校社团办过一次约300人参加的活动，
我负责报名表和现场签到，遇到漏签后提出加一个补签入口，并参与执行。
这是活动方案和报名表。先帮我判断这段经历能写什么，再写一条简历内容。
```

Agent 先核对本人负责什么、哪些安排由本人提出、材料能支持哪些结果。约300人是活动规模，不能写成本人管理了300人团队。没有处理时间或满意度数据时，也不能补出效率提升比例。

在这些事实成立的前提下，简历条目可以写成：

> 负责约300人社团活动的报名表与现场签到，针对漏签提出补签安排并参与执行。

这条内容用于说明活动执行经历。是否适合目标岗位，还要对照岗位说明；缺少的事实继续核实。

## 2. 展开成面试回答

```text
围绕这段经历练习面试。每次只问一个问题，等我回答后再追问。
```

例如，Agent 先问：“为什么要增加补签入口？你当时看到了什么问题？”

你可以根据实际经历回答，再让 Agent 指出哪里缺少本人动作或证据。模拟中不知道的细节就保留为待确认，不把练习时生成的解释写成已经发生的事实。

练习几轮后，可以说：

```text
把我刚才实际回答过的内容整理成一分钟项目介绍，保留还需要确认的地方。
```

## 3. 纠正一个事实

假设你核对原活动方案后发现，补签安排由负责人提出，自己只参与执行：

```text
更正：补签安排不是我提出的，是现场负责人决定后交给我执行的。
请检查这次项目中的简历和面试回答，修改受影响的表述，并告诉我改了哪些文件。
```

简历条目相应改成：

> 负责约300人社团活动的报名表与现场签到，按现场安排执行补签流程。

面试回答也要改为本人怎样执行和处理现场问题，不再保留“我提出了方案”。原说明与更正依据可以保留，当前稿采用更正后的事实。

这是继续当前项目时由 Agent 检查并修改材料的过程。提供相关文件或项目位置，才能核查这次修改实际覆盖了哪些内容。

## 4. 继续制作一份材料

```text
这是目标岗位说明和我的其他两段经历。
请先安排简历内容的取舍和顺序，确认后继续制作一页中文简历。
```

需要英文简历、作品集、网站或投递消息时，说明对应岗位、语言和载体。文件制作使用宿主当前可用的工具；交付时应说明实际生成了哪些文件、还有什么待确认。

## 5. 保存并接着上次

```text
把已确认的经历、当前简历、面试练习的暂停点和待办保存在这个项目文件夹。
```

下次提供同一位置，可以说：

```text
请使用 zane-career-assets，读取这个项目。
沿用上次纠正后的社团经历，接着做活动运营实习的面试练习。
```

普通聊天不能保存文件时，让 AI 给出接续摘要，由你保存并在下次贴回。文件做完、实际投递、参加面试和拿到反馈分别记录。

## 其他开始方式

| 当前任务 | 可以直接说 |
| --- | --- |
| 没有目标岗位 | 这是我的几段经历，请先帮我整理能支持哪些工作任务，再比较可能的岗位方向。 |
| 只改一段简历 | 请使用 zane-career-assets，按这份岗位说明修改这一段，保留已经确认的事实。 |
| 只练面试 | 按这份简历和岗位说明模拟面试，每次问一题，等我回答后再继续。 |
| 收到招聘者反馈 | 对方追问了这几个点，请检查哪些是表达不清，哪些需要补充真实证据。 |
